# 文字层批量校对

## 能完成什么

复用现有 OCR 引擎，新增全库逐页比对和审定修正入口。原始 PDF 不改动；重新识别的候选文件、进度、图片、差异和备份全部放在本地 `.ecc/proofreading/`。

扫描完成只表示每页文字都参加了机器比对。原生文字本身可能乱码，图片页也可能漏识别；不能据此宣称全文逐字校对完成。数字、公式、专名和缺文要对照原件审查。本流程不核验来源观点是否符合现实。

## 已有代码如何复用

| 工作 | 入口 |
|---|---|
| 发现迁移后的原件、逐页比对、续跑、审查和备份修正 | [proofread_batch.py](../scripts/proofread_batch.py) |
| 逐页 OCR、并发、内存节流、失败重试、持久进度 | [ocr_run.py](../scripts/ocr/ocr_run.py) 与 [管道模块](../config/ocr/ocr_pipeline/) |
| 历史九本书配置 | [books.yaml](../config/ocr/books.yaml) |

当前入口是 `scripts/ocr/ocr_run.py`，没有 `scripts/ocr/ocr/_run.py`。新批处理按原件 SHA-256 定位文件，不依赖迁移前的绝对路径或已清空的文字化清单。它会生成独立 OCR 配置，不改旧九本书配置和旧进度。

覆盖实际目录中的 PDF 文字层，包括五本书、普通人、中美博弈、认知红利和原有书籍文字层；排除导航 README、备份、正式文章和课程保护正文。没有 PDF 来源或页码结构不完整的文件会报告异常，不静默当作已校对。

## 使用顺序

在仓库根目录运行。依赖版本见 [requirements-proofreading.txt](../requirements-proofreading.txt)；本机已有所需 Python 包、Tesseract 和中文模型。其他机器仍须安装对应运行环境。

1. 运行全库扫描：`python -X utf8 scripts/proofread_batch.py scan`。再次运行会按原件和文字层哈希跳过未变文件；有修改的文件重新比对。结果是 `.ecc/proofreading/summary.json`、`documents.json` 和 `pages.csv`，完整页文保存在同目录 SQLite 中。
2. 选择需要重新识别的文字层，运行 `ocr --path "资料库/…/文字层/文件.md"`。可重复传入 `--path` 批量选书。默认只生成配置并预检；加 `--run` 才真正调用旧 OCR 引擎。可先加 `--sample 1 --max-workers 2` 做小样本，去掉 `--sample` 才处理全书。抽样与全量使用不同进度库和输出目录。OCR 输入被硬性限制为 `原始资料层` 或本库同义的 `原始资料` 目录中的 PDF；不识别 Markdown、Word、备份和导航文件。
3. 运行 `prepare --path "资料库/…/文字层/文件.md"`，生成每页原图、原生文字、待编辑文本和 `review.json`。默认包含全部页；可用 `--pages 1,3-5` 限定范围。长图会完整切成带重叠的片段，不只截取顶部。
4. 逐页看图，在对应 `replacement.txt` 中保留完整的该页正文。确认后填写 `review.json` 中的审查者、依据和 `approved: true`。这些记录是审查声明，脚本无法代替审查者判断语义正确性。OCR 候选 PDF 只供对照，不能直接当作审定稿。
5. 运行 `apply --review "审查文件的绝对路径"` 预览差异；确认后加 `--write` 写入该份文字层。每次先保存独立备份、审查记录和差异，再核对原件与正文哈希；版本变化会拒绝覆盖。多份资料逐份审定和应用。

以上子命令都接在 `python -X utf8 scripts/proofread_batch.py` 后。完整参数见 `--help`。更换工作区使用全局参数 `--work-dir .ecc/其他目录`，须放在子命令之前。

指定系列的“原件识别后与文字层对比”使用 [ocr_compare_text_layers.py](../scripts/ocr_compare_text_layers.py)。默认复用 PDF 已有内嵌文字，只对纯图片页做本机 Tesseract OCR；`--force-ocr-all` 才会强制每页重新识别。结果保存在 `.ecc/ocr-text-comparison/`，不会写回文字层。

## 安全与恢复

不要同时用其他工具修改正在审查的同一文件。哈希检查能拒绝已发现的并行修改，但不构成对其他程序的文件锁。

未审定、缺少图像证据、原件或正文已变、目标不在资料库文字层、替换文本混入页标题时，写入会被拒绝。脚本不自动提升 `confidence`，不批量把状态改成“校对完成”。每次修正留下 `proofread_record` 回链。

备份和变更收据在 `.ecc/proofreading/applications/`。如需恢复，应按收据找到对应 `before.md`，先确认恢复不会覆盖之后的修正，再恢复目标文件；不要用旧备份覆盖新工作。

异常退出若残留 `run.lock`，先确认对应进程已经结束再删除锁文件。OCR 失败会保留失败记录并返回非零退出码；“进程结束”不等于所有页面成功。

超长单页 PDF 可能超过 OCRmyPDF 的图像尺寸上限。此时 `ocr --run` 默认改用本机 Tesseract 逐片识别 `prepare` 生成的原件图；每片候选文本单独保存，不自动拼接或写回。可用 `--no-tile-fallback` 禁用回退。

## 验证与限制

回归测试覆盖逐页状态、哈希续跑、迁移路径、长图切片、拒绝未审定修改、并行修改检查、备份、选书与抽样，以及最后一页失败后的重试。真实资料的批处理记录保存在 `.ecc/audits/fulltext-proofreading-20260826/`。

全库视觉逐字校对仍需按页完成；机器结果相同的页面也不能免除视觉核验。修改后仍运行唯一资料库验证入口 `python scripts/validate_vault.py --root .`，不得通过刷新保护哈希来掩盖正文变化。
